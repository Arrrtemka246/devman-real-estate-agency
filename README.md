# Сайт риелторского агентства

Учебный проект Devman «Пишем сайт для риелторов». Сайт показывает список квартир
с фильтрами по городу, цене и новостройкам. В админке доступны поиск по адресу,
городу и собственнику, фильтры, редактирование признака новостройки прямо в списке,
жалобы и лайки. Дата создания объявления защищена от редактирования.

Собственники вынесены в отдельную модель: у квартиры может быть несколько
собственников, у собственника — несколько квартир. На странице квартиры их можно
редактировать через inline; большие связи используют `raw_id_fields`.

## Установка и запуск

Нужен Python 3.10 или новее. В папке проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Задайте в `.env` собственный `SECRET_KEY`. Сгенерировать его можно командой:

```sh
python -c 'from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())'
```

Если нужна учебная база с квартирами, скачайте её из
[первого шага урока](https://dvmn.org/modules/django-orm/lesson/filtering-products/)
и положите в папку проекта под именем `db.sqlite3` **до выполнения миграций**.
Существующую базу перед заменой или обновлением сохраните отдельной резервной копией.
Без учебной базы создаётся пустая база, которую можно заполнить через админку.

```sh
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

Сайт: http://127.0.0.1:8000/.
Админка: http://127.0.0.1:8000/admin/.
Для остановки сервера нажмите Ctrl+C.

## Настройки

- `DEBUG` — режим отладки, для локальной разработки `True`.
- `SECRET_KEY` — секретный ключ Django; хранится только в локальном `.env`.
- `ALLOWED_HOSTS` — разрешённые имена хостов через запятую.
- `DATABASE` — адрес БД, по умолчанию `sqlite:///db.sqlite3`.

Пример конфигурации находится в `.env.example`. Секреты и базы исключены из Git.

## Перенос данных

Миграции последовательно добавляют признак новостройки (год постройки от 2015),
жалобы, лайки и нормализованные телефоны. Затем создаются собственники и связи
с квартирами. Старые поля удаляются только после проверки полного переноса.
Ошибочные телефоны не прерывают миграцию: исходная запись сохраняется у
собственника в поле `source_phone`, нормализованный телефон остаётся пустым.
Исходный формат корректных телефонов также сохраняется.

Повторный запуск дата-миграций не дублирует собственников и связи.
Откат к исходной схеме восстанавливает первоначальные контакты. Если после
обновления добавлено несколько собственников одной квартиры или собственники
без квартир, откат останавливается с понятной ошибкой, поскольку старая схема
не сможет сохранить такие данные. Перед откатом всегда делайте резервную копию БД.

## Проверки

```sh
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test property
```

Тесты проверяют фильтры, поиск и inline в админке, валидацию телефонов, жалобы,
лайки, связи собственников, сохранность исходных записей, повторное выполнение
дата-миграций и безопасный откат.
